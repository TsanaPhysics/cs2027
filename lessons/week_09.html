WLO 1: บูรณาการวิทยาการคำนวณกับวิทยาศาสตร์ (Integration Knowledge)

อธิบายหลักการและกระบวนทัศน์ของวิทยาการคำนวณ (Computational Science Paradigms) ในการแก้ปัญหาทางวิทยาศาสตร์จริง การจำลองระบบพลวัต (Dynamic System Simulation) และการประมวลผลข้อมูลทางวิทยาศาสตร์ (Scientific Data Analytics) เพื่อยกระดับความเข้าใจมโนทัศน์ที่ซับซ้อนของผู้เรียนได้อย่างลึกซึ้ง

WLO 2: การออกแบบสถาปัตยกรรมโครงงาน (Project Architecture Design)

สามารถสังเคราะห์และเขียนข้อเสนอโครงงาน (Project Proposal) ที่ระบุปัญหาทางวิทยาศาสตร์ ออกแบบผังงานสถาปัตยกรรมระบบ (System Architecture Flowchart), ข้อมูลนำเข้าและส่งออก (I/O Specifications), และส่วนต่อประสานกับผู้ใช้ (User Interface Mockup) ได้อย่างสอดคล้องตามมาตรฐาน

WLO 3: การสร้างโค้ดต้นแบบตั้งต้น (Starter Code Prototyping)

พัฒนาโค้ดต้นแบบตั้งต้น (Starter Code Prototype) ในภาษา Scratch หรือ Python 3.11 ที่มีตรรกะแกนกลาง (Core Scientific Logic Engine) สามารถคำนวณหรือแสดงพฤติกรรมทางวิทยาศาสตร์ได้อย่างน้อย 1 โมดูลหลัก และมีความพร้อมในการพัฒนาต่อยอด

WLO 4: การนำเสนอแบบกระชับและการสะท้อนคิด (Pitching & Peer Feedback)

สามารถนำเสนอแนวคิดโครงงาน (The 3-Minute Science Pitch) ได้อย่างกระชับ ตรงประเด็น แสดงคุณค่าทางการเรียนรู้วิทยาศาสตร์ (TPACK) ตลอดจนมีทักษะในการให้และรับฟังข้อเสนอแนะเชิงสร้างสรรค์ (Constructive Peer Feedback) เพื่อปรับปรุงโครงงานอย่างมีจรรยาบรรณ

โค้ดตัวแบบจำลองตั้งต้น (Starter Code Prototype) ภาษา Python 3.11: โปรแกรมจำลองการเคลื่อนที่วิถีโค้ง

ตัวอย่างโค้ดโครงร่างโปรเจกต์ (Starter Code) ที่จัดโครงสร้างแบบโมดูลาร์ มี Type Hints และพร้อมให้นักศึกษานำไปพัฒนาต่อยอดเป็นแอปพลิเคชันเต็มรูปแบบ: 

# ==============================================================================
# โครงการต้นแบบ (Starter Code): Projectile Motion Physics Simulator
# รายวิชา: 4124941 วิทยาการคำนวณสำหรับการสอนวิทยาศาสตร์ | ผศ.ดร.ชีวะ ทัศนา
# ==============================================================================
import math
from typing import List, Tuple, Dict

class ProjectileSimulator:
    """
    คลาสแกนกลางจำลองการเคลื่อนที่แบบโพรเจกไทล์ (Core Physics Engine)
    """
    def __init__(self, initial_velocity: float, launch_angle_deg: float, gravity: float = 9.81):
        if initial_velocity <= 0:
            raise ValueError("ความเร็วต้นต้องมากกว่าศูนย์ (v0 > 0)")
        if not (0 <= launch_angle_deg <= 90):
            raise ValueError("มุมยิงต้องอยู่ระหว่าง 0 ถึง 90 องศา")
            
        self.v0 = initial_velocity
        self.angle_rad = math.radians(launch_angle_deg)
        self.g = gravity
        
        # คำนวณความเร็วในแนวราบและแนวดิ่ง
        self.vx = self.v0 * math.cos(self.angle_rad)
        self.vy = self.v0 * math.sin(self.angle_rad)
        
    def calculate_theoretical_summary(self) -> Dict[str, float]:
        """คำนวณค่าสูงสุดตามทฤษฎีฟิสิกส์: เวลาในอากาศ, ความสูงสูงสุด, ระยะตกไกลสุด"""
        t_flight = (2 * self.vy) / self.g
        h_max = (self.vy ** 2) / (2 * self.g)
        r_max = self.vx * t_flight
        
        return {
            "time_of_flight_s": round(t_flight, 3),
            "max_height_m": round(h_max, 3),
            "max_range_m": round(r_max, 3)
        }
        
    def generate_trajectory_points(self, dt: float = 0.1) -> List[Tuple[float, float, float]]:
        """
        สร้างพิกัดการเคลื่อนที่แบบอนุกรมเวลา (t, x, y) เพื่อนำไปพล็อตกราฟ
        """
        trajectory: List[Tuple[float, float, float]] = []
        t = 0.0
        y = 0.0
        
        while y >= 0:
            x = self.vx * t
            y = (self.vy * t) - (0.5 * self.g * (t ** 2))
            if y < 0:
                y = 0.0  # ตกถึงพื้น
                trajectory.append((round(t, 2), round(x, 2), round(y, 2)))
                break
            trajectory.append((round(t, 2), round(x, 2), round(y, 2)))
            t += dt
            
        return trajectory

# ------------------------------------------------------------------------------
# ส่วนทดสอบการทำงานของโค้ดต้นแบบ (Starter Code Verification)
# ------------------------------------------------------------------------------
if __name__ == "__main__":
    print("=" * 65)
    print("🚀 เริ่มต้นแบบจำลองการเคลื่อนที่วิถีโค้ง (Projectile Motion Prototype)")
    print("=" * 65)
    
    # กำหนดสถานการณ์: ยิงปืนใหญ่ความเร็ว 25 m/s มุม 45 องศา
    sim = ProjectileSimulator(initial_velocity=25.0, launch_angle_deg=45.0)
    summary = sim.calculate_theoretical_summary()
    
    print(f"ผลการวิเคราะห์ตามทฤษฎี:")
    print(f"• เวลาที่ลอยอยู่ในอากาศ: {summary['time_of_flight_s']} วินาที")
    print(f"• จุดสูงสุด (H_max): {summary['max_height_m']} เมตร")
    print(f"• ระยะตกไกลสุด (R_max): {summary['max_range_m']} เมตร")
    
    print("\nตัวอย่างอนุกรมเวลา 5 วินาทีแรก (t, x, y):")
    print(f"{'เวลา (s)':<12}{'พิกัด X (m)':<15}{'พิกัด Y (m)':<15}")
    print("-" * 42)
    points = sim.generate_trajectory_points(dt=0.5)
    for t, x, y in points[:8]:
        print(f"{t:<12}{x:<15}{y:<15}")
    print("-" * 42)
    print("✓ โค้ดต้นแบบทำงานถูกต้อง พร้อมเชื่อมต่อ UI และต่อยอดในสัปดาห์ที่ 10")

คำถามท้ายการทดลอง:
  • อัตราการเพิ่มขึ้นของเวลาประมวลผลสอดคล้องกับความซับซ้อน Big-O ระดับใด?
  • เสนอแนะแนวทางการปรับปรุงขั้นตอนวิธีเพื่อลดการใช้หน่วยความจำลงอย่างน้อย 30%

แผนการจัดกิจกรรมการเรียนรู้เชิงรุก (Active Learning: Pitch Fest & Consultation)

กระบวนการเรียนรู้ 4 ชั่วโมง (240 นาที) ที่เปลี่ยนผู้เรียนจากผู้รับความรู้สู่การเป็น "ผู้คิดค้นนวัตกรรมการสอนวิทยาศาสตร์":

ภาคบรรยาย: การเชื่อมโยงสอบกลางภาคสู่โครงงานจริง และ The 3-Minute Pitch ชั่วโมงที่ 1 - 2 (120 นาที)

  • กิจกรรมที่ 1: สรุปผลการสอบกลางภาคและจุดประกายโครงงาน (25 นาที):
    • อาจารย์ผู้สอนสรุปภาพรวมผลการสอบกลางภาค ชี้จุดเด่นที่นักศึกษาเข้าใจได้ดี (เช่น การวิเคราะห์ Flowchart) และจุดที่ต้องระวัง (เช่น Operator Precedence, Silent Logic Errors)
    • เปิดประเด็นสร้างแรงบันดาลใจ: "ในครึ่งแรกของเทอมเราเรียนเพื่อรู้ แต่ในครึ่งหลังเราจะสร้างสรรค์นวัตกรรมจำลองแบบเพื่อไปสอนนักเรียนในโรงเรียนจริง"
  • กิจกรรมที่ 2: อธิบายกรอบแนวคิด The 3-Minute Science Pitch (35 นาที):
    • สาธิตตัวอย่างการ Pitching โครงงานจำลองวิทย์ที่ดีและไม่ดี ผ่านเกณฑ์ 4 มิติ: Problem $\rightarrow$ Solution $\rightarrow$ Demo $\rightarrow$ Impact
    • แจก แบบฟอร์มประเมินเพื่อน (Peer Feedback Rubric Sheet) ประจำกลุ่ม
  • กิจกรรมที่ 3: "Science Project Pitch Fest" (60 นาที):
    • ตัวแทนแต่ละกลุ่ม (กลุ่มละ 3-4 คน) ขึ้นนำเสนอไอเดียโครงงานหน้าชั้นเรียน (กลุ่มละ 3 นาที + ถามตอบข้อเสนอแนะ 2 นาที)
    • เพื่อนร่วมชั้นบันทึกจุดเด่นและข้อเสนอแนะลงในแบบฟอร์มประเมินออนไลน์

ภาคปฏิบัติ: คลินิกให้คำปรึกษาและการลงมือสร้างโค้ดต้นแบบ (Code Clinic Workshop) ชั่วโมงที่ 3 - 4 (120 นาที)

  • กิจกรรมที่ 4: Group Code Clinic & One-on-One Consultation (80 นาที):
    • นักศึกษาแยกย้ายเข้าประจำสถานีคอมพิวเตอร์เพื่อเริ่มร่าง Starter Code Prototype
    • อาจารย์ผู้สอนเข้าประกบรายกลุ่ม (Consulting Stations) เพื่อ:
      • ช่วยคัดกรองขอบเขตเนื้อหาวิทยาศาสตร์ให้อยู่ใน The Sweet Spot ไม่ให้ยากหรือง่ายเกินไป
      • ตรวจเช็กความถูกต้องของสมการธรรมชาติ และช่วยจัดวางสถาปัตยกรรมโมดูลฟังก์ชัน
      • แนะนำคำสั่งหรือไลบรารีที่เหมาะสม (Scratch Blocks, Python Math/Turtle/Matplotlib)
  • กิจกรรมที่ 5: Progress Check & Milestone 10 Commitment (40 นาที):
    • ตัวแทนแต่ละกลุ่มแชร์หน้าจอสรุปความก้าวหน้า (Progress 1 นาที): ได้โค้ดส่วนใดไปแล้ว และจะกลับไปทำอะไรต่อ
    • อาจารย์ย้ำเป้าหมาย Milestone สัปดาห์ที่ 10: "Working Prototype" ต้องมีโปรแกรมที่กดรันและตอบสนองต่อผู้ใช้ได้จริงอย่างน้อย 1 ฟังก์ชันหลัก

เกณฑ์การวัดและประเมินผลตามสภาพจริง (Authentic Assessment Rubrics)

เกณฑ์รูบริกส์จำแนก 4 ระดับคุณภาพ สำหรับการประเมินการนำเสนอโครงงาน (Project Pitch) และความก้าวหน้าของโค้ดต้นแบบ:

เกณฑ์การประเมิน ดีเยี่ยม (4 คะแนน) ดี (3 คะแนน) พอใช้ (2 คะแนน) ปรับปรุง (1 คะแนน)
1. คุณค่าทางการสอนวิทยาศาสตร์ (Pedagogical Value) ระบุปัญหาการเรียนรู้วิทยาศาสตร์ชัดเจน แบบจำลองคอมพิวเตอร์ตอบโจทย์และช่วยให้เด็กเห็นภาพนามธรรมได้อย่างยอดเยี่ยม ปัญหาและเนื้อหาวิทยาศาสตร์มีความชัดเจน แบบจำลองมีความสอดคล้องกับสาระการเรียนรู้ เนื้อหาวิทยาศาสตร์กว้างเกินไป หรือเป็นเรื่องที่ทดลองในห้องเรียนได้ง่ายอยู่แล้วโดยไม่ต้องพึ่งคอมพิวเตอร์ ไม่สามารถระบุปัญหาการเรียนรู้วิทยาศาสตร์ได้ เนื้อหาไม่ถูกต้องตามหลักวิชาการ
2. สถาปัตยกรรมและตรรกะโค้ด (Computational Logic) ออกแบบผังงานระบบถูกต้องตามมาตรฐาน วางโครงสร้าง 3-Tier ชัดเจน มีแกนคำนวณสมการธรรมชาติที่สมบูรณ์ มีผังงานระบบและโครงสร้างฟังก์ชันการคำนวณที่สมเหตุสมผล ผังงานไม่ครบถ้วน หรือตรรกะการคำนวณสูตรวิทยาศาสตร์ยังมีความคลุมเครือ ไม่มีผังงานระบบ และไม่สามารถอธิบายขั้นตอนวิธีของโปรแกรมได้
3. ความก้าวหน้าของโค้ดต้นแบบ (Starter Code Prototype) มี Starter Code ที่รันได้จริง 100% สามารถคำนวณสูตรหลักและแสดงผลลัพธ์ได้อย่างถูกต้อง มีระบบ Guard ป้องกัน Error มี Starter Code ที่รันผ่านในกรณีข้อมูลปกติ แต่ยังไม่ได้จัดการกรณีข้อมูลสุดโต่ง (Edge Cases) มีเฉพาะโครงสร้างฟังก์ชันว่างเปล่ายังรันไม่ได้ หรือยังมี Syntax Error ค้างอยู่ ยังไม่มีการเขียนโค้ดต้นแบบ มีเพียงแนวคิดข้อความเท่านั้น
4. ทักษะการนำเสนอและการตอบคำถาม (Pitching & Communication) นำเสนอได้กระชับ ชัดเจนภายใน 3 นาที สื่อสารได้น่าสนใจ ตอบคำถามและรับฟังข้อเสนอแนะได้อย่างยอดเยี่ยม นำเสนอได้ตามขั้นตอน มีความชัดเจน สื่อสารตรงประเด็นส่วนใหญ่ นำเสนอเกินเวลามาก หรือสื่อสารวกวน ไม่สามารถชี้จุดเด่นของโครงงานได้ ขาดความพร้อมในการนำเสนอ ไม่สามารถตอบคำถามเกี่ยวกับโครงงานของตนเองได้
การประเมินเพื่อพัฒนา (Formative Assessment): การประเมินในสัปดาห์นี้เน้นการให้คำปรึกษาและข้อเสนอแนะเชิงลึก (Formative Feedback) เป็นหลัก คะแนนการมีส่วนร่วมและความก้าวหน้าจะถูกบันทึกเป็นคะแนนสะสม 5% ของโครงงาน

ข้อสอบวัดสมรรถนะขั้นสูงเชิงการคิดคำนวณ (HOTS Assessment Bank)

แบบทดสอบวัดทักษะการคิดขั้นสูง (Higher-Order Thinking Skills: HOTS) ด้านการวิเคราะห์ขอบเขตโครงงาน (Analyzing) และการประเมินตรรกะแบบจำลองวิทยาศาสตร์ (Evaluating) ตามแนวทาง สสวท.:

ข้อที่ 1 (ระดับการวิเคราะห์และการกำหนดขอบเขต - Analyzing & Scoping):
กลุ่มนักศึกษาครูวิทยาศาสตร์ต้องการพัฒนาโครงงาน Scratch เพื่อจำลองเรื่อง "ระบบนิเวศในตู้ปลา (Aquarium Ecosystem)" สำหรับนักเรียนชั้นมัธยมศึกษาปีที่ 3 สมาชิกในกลุ่มเสนอให้ใส่ตัวแปรต่อไปนี้ลงในแบบจำลองทั้งหมด:
1) จำนวนปลาหางนกยูง, 2) ปริมาณออกซิเจนละลายน้ำ (DO), 3) อุณหภูมิน้ำ, 4) ค่าความเป็นกรด-ด่าง (pH), 5) ปริมาณแอมโมเนียจากมูลปลา, 6) ชนิดของแบคทีเรียไนตริฟายอิง, 7) ปริมาณแสงแดดตามมุมองศาดวงอาทิตย์, และ 8) ความเค็มของน้ำทะเล
ในฐานะครูที่ปรึกษาโครงงาน หากประยุกต์ใช้ การคิดเชิงนามธรรม (Abstraction) และ เมทริกซ์ความซับซ้อน (Feasibility Matrix) ข้อใดให้คำแนะนำในการตัดทอนตัวแปรเพื่อให้อยู่ใน "พื้นที่ทองคำ (Sweet Spot)" ได้เหมาะสมที่สุด?
  • ก. ควรเก็บตัวแปรทั้งหมดไว้ เพราะแบบจำลองทางวิทยาศาสตร์ที่ดีต้องเลียนแบบธรรมชาติให้ครบ 100% ทุกรายละเอียด
  • ข. ควรตัด "ความเค็มของน้ำทะเล" (เพราะตู้ปลาหางนกยูงเป็นน้ำจืด) และตัด "มุมองศาดวงอาทิตย์" ออกเนื่องจากเป็นรายละเอียดปลีกย่อยเกินระดับ ม.3 แล้วมุ่งเน้นเฉพาะความสัมพันธ์หลักระหว่าง "จำนวนปลา, ปริมาณออกซิเจน (DO), และของเสียแอมโมเนีย" เพื่อให้โค้ดมีความเป็นไปได้และผู้เรียนเข้าใจมโนทัศน์สมดุลนิเวศได้ตรงประเด็น
  • ค. ควรตัดตัวแปรวิทยาศาสตร์ทั้งหมดออก แล้วเปลี่ยนโครงงานเป็นเกมตกปลาเพื่อความสนุกสนานของนักเรียน
  • ง. ควรเปลี่ยนภาษาโปรแกรมไปใช้ภาษาซีระดับล่าง (C++) เพื่อให้สามารถคำนวณตัวแปรทั้ง 8 ตัวได้รวดเร็ว
เฉลยข้อ ข. ถูกต้อง!
การวิเคราะห์เชิงวิชาการ (Abstraction & Pedagogical Feasibility):
  • หนึ่งในข้อผิดพลาดที่พบบ่อยที่สุดของนักศึกษาในการทำโครงงานคือ "Over-Engineering" พยายามนำตัวแปรจริงทั้งหมดในธรรมชาติมาเขียนโค้ด ซึ่งทำให้แบบจำลองซับซ้อนเกินไป จนเกิดข้อผิดพลาดและเสร็จไม่ทัน
  • หัวใจของ Abstraction (การคิดเชิงนามธรรม) คือการ "คัดเลือกเฉพาะสาระสำคัญที่จำเป็นต่อการเรียนรู้ และละทิ้งรายละเอียดปลีกย่อย"
  • สำหรับระดับ ม.3 การเข้าใจวัฏจักรไนโตรเจนและสมดุลออกซิเจนของสิ่งมีชีวิตในน้ำ คือมโนทัศน์แกนกลาง การเลือกโฟกัสที่ จำนวนปลา $\leftrightarrow$ DO $\leftrightarrow$ ของเสีย จึงจัดเป็น Sweet Spot ที่สมดุลระหว่างความลึกซึ้งทางวิทยาศาสตร์และความเป็นไปได้ในการเขียนโค้ด
ข้อที่ 2 (ระดับการประเมินค่าและให้ข้อเสนอแนะ - Evaluating & Peer Feedback):
กลุ่มเพื่อนนำเสนอ Starter Code ของแบบจำลอง "การแพร่ของสารละลายด่างทับทิมในน้ำที่มีอุณหภูมิต่างกัน" ในภาษา Python โดยเขียนฟังก์ชันคำนวณอัตราการแพร่ดังนี้: 
def calculate_diffusion_rate(temperature_celsius):
    # อุณหภูมิยิ่งสูง อนุภาคยิ่งเคลื่อนที่เร็ว
    diffusion_rate = temperature_celsius * 0.5
    return diffusion_rate
พิจารณาข้อเสนอแนะเชิงสร้างสรรค์ (Constructive Feedback) ข้อใดสามารถยกระดับฟังก์ชันนี้ให้มีความสมบูรณ์ทางฟิสิกส์และวิทยาการคำนวณได้ดีที่สุด?
  • ก. ฟังก์ชันถูกต้องสมบูรณ์แล้ว ไม่จำเป็นต้องแก้ไขใดๆ
  • ข. ควรเพิ่ม Defensive Guard ตรวจสอบอุณหภูมิต่ำสุด เพราะหากผู้ใช้ป้อนอุณหภูมิ $T \le -273.15^\circ\text{C}$ (ต่ำกว่าศูนย์สัมบูรณ์) หรือน้ำแข็งตัว ($T \le 0^\circ\text{C}$) สารละลายจะหยุดการแพร่หรือเปลี่ยนสถานะ ฟังก์ชันจึงไม่ควรคืนค่าอัตราการแพร่ติดลบ
  • ค. ควรเปลี่ยนตัวแปร temperature_celsius ให้เป็นสตริง (String) เพื่อให้อ่านค่าง่ายขึ้น
  • ง. ไม่ควรใช้สูตรคณิตศาสตร์ในการเขียนโปรแกรม ควรใช้การสุ่มค่า random() ล้วนๆ
เฉลยข้อ ข. ถูกต้อง!
การประเมินค่าเชิงบูรณาการวิทยาศาสตร์และคอมพิวเตอร์:
  • ฟังก์ชันเดิมมีช่องโหว่ทางฟิสิกส์อย่างรุนแรง: หากป้อนอุณหภูมิติดลบ เช่น $-10^\circ\text{C}$ จะได้ diffusion_rate = -5.0 ซึ่งในความเป็นจริง น้ำกลายเป็นน้ำแข็งไปแล้ว และอัตราการแพร่ไม่สามารถติดลบได้
  • ข้อเสนอแนะที่แสดงสมรรถนะครูวิทยาศาสตร์ระดับสูง คือการชี้แนะให้ใส่ Defensive Guard เช่น if temperature_celsius <= 0: return 0.0 และจำกัดขอบเขตอุณหภูมิไม่ให้เกินจุดเดือด ($100^\circ\text{C}$) เพื่อสะท้อนกฎธรรมชาติอย่างสมจริง
